# Backend

Follow the project-level `AGENTS.md` and `docs/PLAN.md`.

- `app/main.py` defines the FastAPI app, initializes SQLite at startup, restricts hosts to loopback names, rejects request bodies over 4 MiB, adds security headers (`frame-ancestors 'none'`, `nosniff`, `Referrer-Policy`), registers the authentication and board routers and the `/api/health` route used by the Docker healthcheck, and mounts static files at `/`. Register API routes before the static mount.
- `app/auth.py` implements the fixed local login, eight-hour in-memory sessions, an HTTP-only SameSite Strict cookie, logout (which always clears the cookie, even for an expired session), and same-origin checks for state-changing auth requests. Sessions are cleared when the server restarts. This is not production authentication.
- `app/database.py` initializes the versioned SQLite schema (version 2; a version 1 database is migrated at startup by truncating text over the board limits and restoring blank column titles to their defaults), enables WAL mode, and provides connections with foreign keys enabled and explicit transactions. Compose sets `DATA_DIR=/data`, so the database is `/data/kanban.sqlite3`.
- `app/board.py` exposes authenticated `GET /api/board` and same-origin authenticated `PUT /api/board`, validates fixed columns, card consistency, non-blank titles, and size limits (card title 200, details 5000, column title 100 characters; 500 cards), seeds one board per user, serves reads without the write lock unless the board must be created, and applies revision-checked updates atomically. See `docs/database-approach.md` for the API contract.
- `app/ai.py` exposes authenticated, same-origin `POST /api/ai/check` and `POST /api/ai/chat` routes. Chat sends the current board and conversation to the configured OpenRouter model with required Structured Outputs. The model returns a list of `create`, `update`, and `move` operations (at most 25); the server applies them to the current board, validates the result with the board model, and saves it through the revision-checked transaction. Deleting cards is not expressible, and the server assigns IDs to new cards. For an HTTP 400 the provider's own error message (such as a context-length error) is returned; a timeout returns 504.
- `app/initial_board.json` is the shared initial board for the backend and frontend. A frontend test checks it against the approved schema document.
- The Docker build copies the Next.js static export to `app/static/` in the image; that directory is not maintained as backend source.
- `pyproject.toml` and `uv.lock` define Python dependencies; the Docker image uses `uv` to install them.
- `tests/test_main.py` tests the exported page and JavaScript asset, the API, and a missing API route. `tests/test_auth.py` covers sessions, credentials, logout, expiration, and request-origin/host restrictions. `tests/test_board.py` exercises board operations, validation, user isolation, concurrent conflicts, rollback, and initialization. `tests/test_ai.py` mocks OpenRouter responses and checks authentication, configuration, provider failures, Structured Outputs validation, context, operation handling and rejection, and revision conflicts. The Dockerfile's `test` stage builds the frontend and runs the backend tests.
- Compose mounts the persistent `board-data` volume at `/data`; the frontend uses the authenticated board API and offers optional import of previous tab data.
